# Клиенты

Точечная проверка номеров перед созданием счёта или подписки. Поможет не выставлять счёт на номер, у которого нет приложения Kaspi (такой счёт уйдёт в статус `error` с понятным `error_message`, но впустую займёт квоту).

> ⚠️ **Запрещено использовать эндпоинт для массового перебора номеров (enumeration).** Эндпоинт предназначен для разовой проверки номера уже известного клиента — перед созданием счёта, подписки или возвратом. При использовании не по назначению API-ключ деактивируется без предупреждения. Лимиты — 60 запросов в минуту и 10 000 в сутки на API-ключ.

## Проверка номера

**Эндпоинт:** `POST /clients/check`

Проверяет, зарегистрирован ли номер в Kaspi, и возвращает имя клиента (если есть).

### Запрос

```bash
curl -X POST https://api.apipay.kz/api/v1/clients/check \
  -H "X-API-Key: YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"phone": "77001234567"}'
```

### Параметры

| Поле | Тип | Обязательно | Описание |
|------|-----|-------------|----------|
| `phone` | string | Да | Телефон клиента. Принимает `77XXXXXXXXX`, `87XXXXXXXXX`, `+77XXXXXXXXX`, с пробелами/дефисами. После нормализации должен дать 11 цифр. |

**Нормализация:** первая цифра `7` или `+7` заменяется на `8`; пробелы, дефисы и плюсы удаляются. Любой формат, который после нормализации даёт 11 цифр, принимается.

### Ответ 200

```json
{
  "phone": "87001234567",
  "has_kaspi": true,
  "client_name": "Иван И."
}
```

| Поле | Тип | Описание |
|------|-----|----------|
| `phone` | string | Номер в нормализованном виде (`8XXXXXXXXXX`, 11 цифр). |
| `has_kaspi` | boolean | `true` — у клиента установлен Kaspi и он зарегистрирован. `false` — клиент не найден; создавать счёт на этот номер нельзя. |
| `client_name` | string \| null | Имя клиента из Kaspi в формате «Имя Ф.». `null` если `has_kaspi=false`. |

### Ошибки

| Статус | Тело | Когда |
|--------|------|-------|
| `401` | `{"error": "Invalid API key", "message": "..."}` или `{"error": "API key is missing", ...}` | Неверный или отсутствующий `X-API-Key`. |
| `422` | `{"error": "Validation failed", "field": "phone", "message": "..."}` | `phone` пустой, отсутствует или не нормализуется к 11 цифрам. |
| `429` | `{"message": "Too Many Requests"}` | Превышен общий per-key лимит (60/мин или 10 000/сутки). Смотрите заголовок `Retry-After`. |

См. также раздел [Ошибки и лимиты](errors.md).

### Типичный сценарий

```javascript
// Перед созданием счёта/подписки
const check = await fetch('https://api.apipay.kz/api/v1/clients/check', {
  method: 'POST',
  headers: { 'X-API-Key': KEY, 'Content-Type': 'application/json' },
  body: JSON.stringify({ phone: customerPhone })
}).then(r => r.json())

if (!check.has_kaspi) {
  // Сообщите клиенту, что для оплаты нужен установленный Kaspi
  return showError('Этот номер не зарегистрирован в Kaspi. Укажите другой.')
}

// Имя из Kaspi можно показать пользователю как подтверждение
showConfirmation(`Выставить счёт ${check.client_name} (${check.phone})?`)
```
