# Начало работы

## Подготовка

Начинайте с песочницы: анкета о бизнесе и кассир для неё не нужны.

1. **Зарегистрируйтесь** на [apipay.kz/login](https://apipay.kz/login) — вход по номеру телефона через WhatsApp. Новая организация создаётся в песочнице: счета не уходят в Kaspi, деньги не двигаются.
2. **Получите API ключ** в Настройки → Подключение. Ключ один и тот же для песочницы и рабочего режима — переключение режима его не меняет.
3. **Встройте и проверьте интеграцию в песочнице** — оплату, отмену, истечение, ошибку, возврат и отказ в возврате, повторную доставку уведомления. Как заказать каждый исход — [Песочница](sandbox.md).
4. **Переведите организацию в рабочий режим** — анкета о бизнесе, кассир Kaspi, тариф и переключение, см. [Путь в рабочий режим](#путь-в-рабочий-режим).

## Конфигурация

| Параметр | Значение |
|----------|----------|
| Base URL | `https://api.apipay.kz/api/v1` |
| Аутентификация | Заголовок `X-API-Key: your_api_key` |
| Content-Type | `application/json` |
| Rate Limit | 200 запросов/минуту на API-ключ. Отдельные эндпоинты: `POST /clients/check` — 60/мин и 10 000/сутки, `POST /invoices/qr` — 200/мин на организацию, `GET /invoices/{id}` — 1000/мин, `POST /invoices/bulk` — 20/мин, `POST /catalog/scan` — 30/мин и 2000/сутки |

## Первый счёт

```bash
curl -X POST https://api.apipay.kz/api/v1/invoices \
  -H "X-API-Key: YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"amount": 10000, "phone_number": "87001234567"}'
```

Ответ:
```json
{
  "id": 124,
  "amount": "10000.00",
  "status": "processing",
  "paid_at": null,
  "phone": "87001234567",
  "is_imported": false,
  "created_at": "2026-01-15T10:00:00+00:00"
}
```

Клиент получит уведомление в приложении Kaspi и сможет оплатить. В песочнице оплату изображает `POST /invoices/{invoice}/simulate-status` с `{"status": "paid"}`.

## Путь в рабочий режим

Порядок: **песочница → анкета о бизнесе → проверка анкеты → кассир Kaspi → тариф → перевод в рабочий режим.** Всё это делает человек в кабинете.

### 1. Анкета о бизнесе

Короткая анкета «Расскажите о вашем бизнесе» (~5 минут в кабинете, `/business-profile`): что продаёте, где продаёте, примерный средний чек, ссылка на точку продаж и скриншоты. Название организации и БИН или ИИН вводит сам владелец. Данные из анкеты нужны, чтобы настроить лимиты под ваши обороты. Анкету проверяет ApiPay; статус проверки виден в кабинете.

Пока анкета не одобрена, боевые счета не выставляются вовсе: первый же `POST /invoices` (а также `POST /invoices/qr` и счета подписок) вернёт `429 kyc_daily_limit_reached` — в `meta.limit` придёт `0`, а в `meta.reset_at` — окно суток. Ждать нового окна бесполезно: ограничение снимает одобрение. В песочнице это ограничение не действует. Если у организации есть `kyc_deadline` в будущем (грейс), до дедлайна ограничение не действует.

### 2. Кассир Kaspi

⛔ До одобрения анкеты кассира подключить нельзя: `POST /connections/{id}/auth/init` и `POST /connections/{id}/auth/send-phone` отвечают `403 kyc_required`, SMS кассиру при этом не отправляется.

После одобрения — мастер в кабинете: [apipay.kz/connect-cashier](https://apipay.kz/connect-cashier) (Настройки → Авторизация Kaspi). Занимает 2–3 минуты: добавьте номер сотрудника с ролью **«Кассир»** в приложении Kaspi Pay (Настройки → Сотрудники), введите этот номер в мастере и подтвердите код из SMS. Подробная инструкция — [гайд «Как подключить свою Kaspi-кассу»](https://apipay.kz/guides/podklyuchenie-kassira-kaspi).

> **Важно:** после привязки не входите в приложение Kaspi Pay под номером кассира — сессия разорвётся и кассира придётся подключать заново.
>
> Если мастер не проходит, поможем вручную: [WhatsApp поддержки (+7 700 307 65 12)](https://wa.me/77003076512).

### 3. Тариф и перевод

Оплатите тариф в кабинете и переключите организацию в рабочий режим (Настройки, кнопка «Переключить в рабочий режим»; роли Владелец и Разработчик). При переводе песочные данные организации удаляются — тестовые счета, возвраты, ссылки покупателю на возврат, подписки и позиции каталога; нужное выгрузите заранее. Ссылки на оплату и печатные QR-листы из песочницы не удаляются и остаются тестовыми — покупателям выпустите новые уже в рабочем режиме, а старые отключите. Тот же API-ключ после перевода выставляет настоящие счета. После переключения `GET /account/health` отдаёт `mode: production`.

Перед переводом:

- для ещё не одобренных организаций рабочий webhook должен быть на реальном домене — IP и туннели (ngrok) отклоняются (см. [Webhooks](webhooks.md));
- уберите `simulate` и магические номера песочницы из боевого кода;
- в рабочем режиме после проверки подписи отбрасывайте события с `is_sandbox: true` в корне тела: отвечайте `2xx` и не исполняйте. Событие по песочному объекту, отправленное до перевода организации в рабочий режим, может прийти уже после него. Подробнее — [Webhooks](webhooks.md).

## Подключение с ИИ-помощником

Интеграцию можно поручить ИИ-помощнику (Claude Code, Codex, Cursor и другие). Сначала — песочница, без настоящих денег.

**С MCP.** Экран [«Подключить с ИИ»](https://apipay.kz/setup/ai) в кабинете (Настройки → Подключение) даёт готовую настройку для вашего ИИ-клиента. Адрес сервиса — `https://mcp.apipay.kz/mcp`, имя сервера — `apipay-setup`. Для Claude Code:

```bash
claude mcp add --transport http --scope user apipay-setup 'https://mcp.apipay.kz/mcp'
claude mcp login apipay-setup
```

Дальше скажите помощнику: «Встрой apipay.» Помощник ведёт подключение по шагам: изучает проект, задаёт недостающие вопросы, пишет код и проверяет обязательные исходы в песочнице. Проверки в песочнице помощник делает после вашего входа в ApiPay в браузере; в Cursor вход в ApiPay не поддерживается — помощнику доступны только поиск по документации и план подключения. API-ключ для входа в MCP не используется и в настройки ИИ-клиента не добавляется.

**Без MCP.** Дайте помощнику короткую инструкцию [apipay.kz/SKILL.md](https://apipay.kz/SKILL.md) и плейбук [apipay.kz/for-ai.md](https://apipay.kz/for-ai.md). Готовый серверный код по способу оплаты и стеку — [рецепты](https://apipay.kz/recipes/index.md), машиночитаемо — [apipay-recipes.json](https://apipay.kz/apipay-recipes.json).

Что остаётся за человеком:

- выпуск ключа и секрета подписи уведомлений — значения вставляет человек сам в переменные окружения сервера, в чат их не передают;
- анкета о бизнесе: помощник может подготовить черновик, но название организации, БИН или ИИН, скриншоты и отправку делает человек. Срок проверки анкеты помощник не обещает — статус видно в кабинете;
- кассир Kaspi с кодом из SMS, оплата тарифа и перевод в рабочий режим.

Доступ помощника выдаётся на экране согласия: человек отмечает организации, с которыми помощник будет работать. Боевую организацию помощник получает только по отдельному разрешению — Настройки → «Кто имеет доступ к организации» → «ИИ-агенты»; там же доступ отзывается. После перевода организации в рабочий режим это разрешение нужно дать заново.

> ⚠️ Готового SDK у ApiPay нет. Пакеты с именем `apipay` в npm и похожие имена в PyPI и Packagist к ApiPay.kz отношения не имеют — не устанавливайте их.
